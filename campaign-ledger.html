Campaign ledger

A ledger with a defined schema and zero rows. That is the honest state: no click, session or order figure can be obtained from an authorised first-party report yet, so none is shown.

Why this page is empty

Every number a marketing dashboard normally shows — sessions, clicks, conversion rate, earnings per click — comes from a report. We do not have an authorised report. Filling this table with estimates would make the page look finished and the site dishonest. So the columns exist, the provenance rule is written down, and the table waits.

Schema v1. Rows are added only from an authorised first-party report, each with its date and source.
Date (UTC)Source report ChannelEligible sessions Outbound clicksReported orders Provenance note
No rows. No authorised first-party report has been supplied (Q-04); the five browser-local events that could feed it are defined on the measurement schema. Empty by design — nothing is inferred.

What is measured today, and where

Five events are defined and counted in the reader's browser: page_view, outbound_click, guide_read, search and suggestion_rank. They are stored in local storage, never transmitted, and can be exported to CSV from the disclosure page. That is useful for understanding your own session; it is not a substitute for a server-side report, and this page does not pretend otherwise.

The rules this ledger follows

  1. One row per report, not per day. A row without a report is not a row.
  2. Every row carries the date it was obtained and the system it came from.
  3. Nothing is inferred, back-filled, or smoothed between reports.
  4. Where a report is incomplete, the missing cells stay blank.
  5. No conversion score and no revenue forecast is derived from this table.

The blocking dependency is Q-04: until one tagged link is confirmed in the tracking report, there is nothing to record.
