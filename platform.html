AI Affiliate Platform Architecture & Compliance Gates

An AI-assisted affiliate workflow is only as reliable as its verification sources and policy gates. Below is the subsystem blueprint for this site — what already runs in the repository today, what is blocked by Amazon Associates eligibility or policy rules, and why automation never publishes without passing the gate.

2. Hard policy boundaries for AI and automation

  • No ML or LLM training on Amazon Program Content (Program Policies, Participation Requirements §5 & IP License §1, §2(e)): Affiliates may not use Special Links, Program Content, Creators API, PA API, or Data Feeds to develop, train, or fine-tune machine learning models, LLMs, or related technologies without Amazon's express prior written approval. All editorial copy on this site is generated deterministically by Python from audited local JSON registers, never trained into model weights.
  • Agent identification & anti-evasion (IP License §4 Agent Terms): Any software agent accessing Program Content must identify itself in HTTP User-Agent headers as Agent/[agent name], must never mimic human browsing or bypass CAPTCHAs/checkpoints, and must stop immediately if Amazon requests exclusion.
  • No link cloaking or hidden redirects (Program Policies §6(v), §6(w) & Commission Income Statement §2(e)): Readers must always see clearly that they are clicking a paid link to Amazon. Redirecting links without user action can disqualify commissions.
  • No cached Amazon images or unrefreshed API prices (IP License §2(h), §2(i), §2(k)): Until Creators API credentials exist, this site uses captioned generated editorial imagery (assets/photos/, FLG-036) plus original SVG schematics (assets/illustrations/) and leaves price/availability fields blank by policy (FLG-005, FLG-007).

3. Deterministic 7-stage publishing pipeline

  1. Fetch & snapshot: Read official listings and policy docs; log URLs and dates in data/sources.json and data/reverification-2026-11-20.json.
  2. Reconcile conflicts: Record contradictory listing figures with "st": "conflict" and assign a flag ID in data/flags.json rather than picking one number.
  3. Redact unverified fields: Leave unstated specs null (st: "unverified") and omit prices/ratings per Program Policies §2(b) and §6(t).
  4. Render deterministically: Build all pages, sitemap.xml, feed.xml, robots.txt, and the client search index via python3 scripts/build_site.py.
  5. Gate before publish: Run python3 scripts/check_site.py and automated tests locally and in GitHub Actions (.github/workflows/pages.yml) to block drift or policy violations.
  6. Measure with zero cookies: Count the five defined events in browser storage or a self-hosted endpoint configured per Measurement & Collector.
  7. Human decision gate: Rank new features on Decision Center and verify Associates tracking (Q-04) before scaling traffic.
