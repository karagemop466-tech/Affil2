Measurement

Five first-party events, one self-hosted collector, and a ledger that stays empty until an authorised report fills it. Nothing here is inferred, and nothing is estimated.

What this site records

Five events are defined and only these five are accepted. The collector rejects anything else with a 400, so a stray or hostile payload cannot be stored.

Event schema. The authoritative copy lives in data/events.json; the collector enforces it in code.
EventFires whenPayloadWhy it exists
page_viewEvery full page load.path, referrer host, session idThe denominator. Every other number is meaningless without it.
outbound_clickA reader clicks a sponsored Amazon link.path, product id, link position, session idThe only first-party number that measures intent to buy.
guide_readThe footer of a guide scrolls into view — the reader reached the end.path, guide id, session idSeparates a guide that was opened from a guide that was read.
searchA search results page has a query.path, query length, result count, session idShows what readers cannot find by browsing. It records the shape of a search, never the words typed.
suggestion_rankA reader moves a suggestion up or down the register.path, suggestion id, position, session idShows which directions readers think should be built first, without a form.

What is never collected

  • No cookies, no local storage, no advertising identifiers, no cross-site tracking.
  • No IP address, no user agent, no device fingerprint or any derived identifier.
  • No query strings, no hash fragments, no referrer URL — only the bare hostname of a different site, and only when one exists.
  • The text of a search query is never sent or stored. Its length and the number of results returned are.
  • Any payload key outside the documented schema is dropped rather than stored.
  • The session id is random per page load, 18 characters, and dies with the tab. Sessions can be counted; people cannot be profiled.

The reader-visible counter in the Campaign Ledger is separate and stays in the reader's own browser. It is a local convenience, not a measurement system.

The self-hosted collector

GitHub Pages serves static files and cannot run a server-side function, so the collector ships in this repository in three deployable forms. All three answer the same contract.

Three implementations of one contract. All share the same sanitisation rules, so they cannot drift.

Pointing the site at a collector. The collector is same-origin by default. To use one on a different host, add this to the <head> of every page:

<meta name="x-collect-endpoint" content="https://collector.example/collect">

While no collector answers, nothing happens. The browser client sends one GET to the endpoint on each page load. If it does not return 200, the whole module stays inert: no event is sent, no storage is touched, and the reader sees nothing. That is the state of the live site today, and it is deliberate — see Flagged for Review, FLG-036.

Contract. POST /api/collect with a JSON body returns 204 for an accepted event and 400 for anything outside the schema. GET /api/collect returns 200 {"status":"ok"} and stores nothing. Bodies over 4 KB are refused with 413.

What the collector does not measure

Server-side numbers come from Amazon, not from us. They are transcribed by hand, with provenance.
NumberWhere it comes from
OrdersThe Associates Central orders report, transcribed into the campaign ledger by hand with the report date and a link to the report.
CommissionThe same first-party report. Never estimated.
Conversion rateOrders divided by clicks, and only once both sides are real. No proxy conversion rate is published.

Until a real report exists, the campaign ledger stays empty. An empty ledger is the honest starting point; a filled one with invented numbers would not be.

How a number gets used

  1. page_view gives the denominator for every rate on the site.
  2. outbound_click gives intent to buy, per product and per placement — the number that decides which guide to write next.
  3. guide_read separates a guide that was opened from a guide that was finished, and therefore says which topics deserve more coverage.
  4. search shows what readers are looking for and not finding, which is the cheapest editorial signal available.
  5. suggestion_rank shows which directions readers think should be built first.

None of these are used to claim a revenue figure, a popularity ranking or a conversion rate. They are used to decide what to write and what to fix.

How this site earns trust

  1. Disclosure above the fold on every page, repeated in the footer.
  2. Every buy link is marked (paid link), carries rel="sponsored nofollow", and carries the Associates tracking tag. Links kept only for verification are labelled as such and stay rel="sponsored nofollow".
  3. Intended vs observed ASINs are stored in separate fields — never merged.
  4. Blank means unverified. We do not infer prices, ratings or popularity.
  5. Measurement is first-party, cookie-free, and self-hosted. If no collector is deployed, nothing is collected.
